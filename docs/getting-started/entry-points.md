# Entry Points and Use Cases

OpenDC can be used from the command line, from a browser, from Python, and from Kotlin or Java. This page describes
what the four *entry points* have in common, what each is suited for, and how to choose between them.

## One model, four entry points

Every entry point describes a simulation in the same way: as an *experiment*, which names the datacenter designs,
workloads and policies to simulate. The [experiment document](../reference/experiment/index.md) is the JSON form of
this description. Every entry point also uses the same simulator and produces the same
[output files](../reference/output/index.md). Figure 1 shows how the entry points build on shared parts.

``` mermaid

    python["Python SDK<br><code>opendc-sdk</code>"] --> model

    cli -.->|"--api-url"| server
    python -.->|"Server"| server

        model["Model<br>describes an experiment"] --> runner["Runner<br>simulates it"]

```

Two consequences follow from this design. An experiment written for one entry point works with the others: a JSON file
exported from the web application runs with the command line, and the Python SDK reads the same file. Results are also
comparable across entry points, because all of them come from the same simulator.

## The entry points

### Command line

The `opendc` command reads an experiment from a JSON file, simulates it on the local machine and writes the results as
Parquet files. It needs Java and no other software.

The command line suits these uses:

- a study that should be reproducible from files under version control;
- large batches of scenarios on a compute node, where no browser is at hand;
- automated runs, for example in continuous integration.

[First Experiment](first-experiment.md) introduces the command, and [Command Line](../reference/cli.md) documents it.

### Web application

The web application offers OpenDC in the browser, backed by a server. It has an editor that draws a datacenter as a
floor plan, forms for the settings of an experiment and charts that compare scenarios while they run. The server
simulates on its own machine or on a cluster, and keeps experiments, traces and results for a team.

The web application suits these uses:

- teaching, because students need nothing but a browser;
- exploring a design visually before studying it in depth;
- teams that share topologies, traces and results;
- simulations that are too large for a laptop.

A hosted deployment runs at [app.opendc.org](https://app.opendc.org). [OpenDC as a Service](../web/index.md) describes
the web application and how to host it.

### Python SDK

The Python software development kit (SDK) is the package `opendc-sdk`. It builds experiments in Python, simulates them
inside the Python process or on a server, and returns every output table as a pandas DataFrame.

The Python SDK suits these uses:

- analysis in notebooks, where simulation and plotting belong together;
- experiments that are generated by code, such as a sweep over hundreds of host counts;
- workloads that already exist as DataFrames.

[Python SDK](../python-sdk/index.md) documents it.

### Kotlin SDK

The Kotlin SDK consists of two libraries for the Java virtual machine (JVM). The *model* describes an experiment as
plain data, and the *runner* simulates it. The other three entry points are built on these libraries.

The Kotlin SDK suits these uses:

- programs that embed the simulator, such as a tool that plans capacity;
- processing results while a simulation runs, without writing files;
- extending OpenDC, because it is the layer directly above the simulator.

[Kotlin SDK](../kotlin-sdk/index.md) documents it.

## Choosing an entry point

Table 1 compares the entry points by what a user of each has to provide and receives.

| Entry point     | Experiment is written as        | Simulates on                     | Results arrive as                 | Requires               |
|-----------------|---------------------------------|----------------------------------|-----------------------------------|------------------------|
| Command line    | JSON file                       | local machine, or a server       | Parquet files                     | Java&nbsp;21           |
| Web application | forms and a floor plan          | server or cluster                | charts, CSV, Parquet files        | a browser              |
| Python SDK      | Python code, or a JSON file     | local machine, or a server       | pandas DataFrames                 | Python&nbsp;3.11, Java&nbsp;21 |
| Kotlin SDK      | Kotlin or Java code, or a JSON file | local machine                | typed objects, Parquet files      | a JVM project          |

///

For a first contact with OpenDC, we recommend the command line: it has the fewest moving parts, and the rest of this
section uses it. The web application is the better start for readers who prefer not to install anything.
